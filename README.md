# Тестовое задание QA — Avito

В репозитории представлены результаты выполнения двух заданий: поиск дефектов на скриншотах интерфейса (задание 1) и тестирование API объявлений (задание 2.1).

## Технологии

- Java 21
- Maven
- JUnit 5
- REST Assured
- Jackson (Для преобразования объектов Java в JSON при отправке запросов)

## Структура проекта

```text
├── src/test/java/qa/avito/
│   ├── ApiClient.java
│   ├── AuthTest.java
│   └── ItemTest.java
├── pom.xml
├── Задание_1.md
├── TESTCASES.md
├── BUGS.md
├── PROMPTS.md
└── README.md
```

- `ApiClient.java` — методы для отправки HTTP-запросов к API;
- `AuthTest.java` — тесты регистрации и авторизации пользователей;
- `ItemTest.java` — тесты создания, получения и удаления объявлений, статистики и доступа к защищённым методам API, а также E2E-сценарий;
- `TESTCASES.md` — описание тест-кейсов API;
- `BUGS.md` — потенциальные дефекты, обнаруженные при тестировании API;
- `Задание_1.md` — результаты выполнения первого задания;
- `PROMPTS.md` — сведения об использовании ИИ при выполнении задания.

## Запуск автотестов

### Требования

- Установленный JDK 21;
- Maven 3.9.x;
- Доступ к тестовому стенду: https://qa-internship.avito.com.

Открыть терминал в корне проекта (в каталоге с `pom.xml`) -> необходимые зависимости автоматически загрузятся при первом запуске;

### Windows (PowerShell)

- **Запуск всех тестов**:

```powershell
.\mvnw.cmd clean test
```

- **Запуск тестов регистрации и авторизации**:

```powershell
.\mvnw.cmd "-Dtest=AuthTest" test
```

- **Запуск тестов объявлений**:

```powershell
.\mvnw.cmd "-Dtest=ItemTest" test
```

- **Запуск отдельного тестового метода**:

```powershell
.\mvnw.cmd "-Dtest=ItemTest#deleteItemSuccessfully" test
```

Отчёты Maven Surefire сохраняются в каталоге `target/surefire-reports/`

## Особенности тестирования

- Для тестов создаются уникальные пользователи и собственные тестовые данные;
- После выполнения тестов производится очистка созданных объявлений;
- Пользователи не удаляются, поскольку API не предоставляет соответствующий метод;
- Граничные проверки с неопределёнными бизнес-требованиями фиксируют фактическое поведение API. Потенциальные дефекты описаны в `BUGS.md`.

### Возможные проблемы при запуске

При возникновении ошибки `Connection timed out` необходимо проверить доступность стенда и повторить запуск: 

1. Test-NetConnection qa-internship.avito.com -Port 443
2. .\mvnw.cmd clean test

## Отчёт Allure

После выполнения автотестов результаты сохраняются
в директории `target/allure-results/`

### Windows (PowerShell)

- **Открытие отчёта**:

```powershell
.\mvnw.cmd allure:serve
```

- **Запуск тестов с последующим открытием отчёта**:

```powershell
.\mvnw.cmd clean test allure:serve
```

## Проверка качества кода (линтер и форматтер)

**В проекте используются Checkstyle и Spotless**

- Правила Checkstyle определены в `config/checkstyle.xml`;

### Windows (PowerShell)

Проверка правил оформления:

```powershell
.\mvnw.cmd checkstyle:check
```

Проверка форматирования:

```powershell
.\mvnw.cmd spotless:check
```

Автоматическое форматирование:

```powershell
.\mvnw.cmd spotless:apply
```
