# Дефекты API

### **Окружение:** https://qa-internship.avito.com

## Подтверждённые дефекты

В рамках выполненных проверок однозначных нарушений документированных требований API не было обнаружено;

## Потенциальные дефекты

- Допустимые диапазоны цены и счётчиков статистики не определены в предоставленной коллекции Postman; 
- Все результаты ниже, лишь предположения, которые стоит уточнить для минимизации рисков

### BUG-01 — Создание объявления с отрицательной статистикой

- **Тест-кейс:** TC-16  
- **Метод:** `POST /api/1/item`  
- **Предусловие:** пользователь зарегистрирован и авторизован.

#### **Шаги воспроизведения:**

1. Отправить запрос на создание объявления с корректным `sellerID`, названием и ценой, указав `likes: -1`, `viewCount: 11`, `contacts: 43`;
2. Повторить запрос отдельно с `viewCount: -1` и `contacts: -1`, оставляя остальные поля корректными;
3. Получить созданные объявления через `GET /api/1/item/{id}`.

- **Предполагаемый результат:** HTTP 400, объявление не создаётся, поскольку количество лайков, просмотров и контактов не может быть отрицательным;

- **Фактический результат:** HTTP 200 во всех трёх случаях -> Объявления создаются, отрицательные значения сохраняются;

### BUG-02 — Создание объявления с отрицательной ценой

- **Тест-кейс:** TC-17  
- **Метод:** `POST /api/1/item`  
- **Предусловие:** пользователь зарегистрирован и авторизован.

#### **Шаги воспроизведения:**

1. Отправить запрос на создание объявления с `price: -1`, оставив остальные поля корректными.
2. Получить объявление через `GET /api/1/item/{id}`.

- **Предполагаемый результат:** HTTP 400, объявление не создаётся;

- **Фактический результат:** HTTP 200, объявление создаётся с ценой -1;

### BUG-03 — Отказ в создании объявления с нулевой статистикой

- **Тест-кейс:** TC-15  
- **Метод:** `POST /api/1/item`  
- **Предусловие:** пользователь зарегистрирован и авторизован.

#### **Шаги воспроизведения:**

1. Отправить запрос на создание объявления со статистикой `{"likes": 0, "viewCount": 0, "contacts": 0}`, оставив остальные поля корректными;
2. Повторить запрос, установив все три счётчика в 1;

**Предполагаемый результат:** HTTP 200 в обоих случаях, поскольку новое объявление может не иметь лайков, просмотров и контактов;

**Фактический результат:** HTTP 400 при всех нулевых счётчиках; HTTP 200 при всех счётчиках, равных 1;

## BUG-04 — Нестабильный ответ при авторизации

- Тест-кейс: TC-08;
- Endpoint: POST /api/1/autorize;
- Статус: нестабильно воспроизводится;

**Шаги воспроизведения:**

1. Зарегистрировать нового пользователя.
2. Отправить запрос авторизации без поля password.

- **Ожидаемый результат:** HTTP 400;

- **Фактический результат:** при одном из запусков автотестов получен 'HTTP 504 Gateway Timeout';

При ручной проверке через Postman получен HTTP 400 (Причина нестабильного поведения не установлена)
